# Draft app cleanup

`apps delete <uuid>` inventories and deletes a draft app with its verified exclusive primitives. Shared primitives remain; the app's native child cascades still apply. Published/archived app identities are blocked. An app being draft does not imply its workflows are unpublished or its objects have no data.

Start with `apps delete <uuid> --dry-run`: this is offline intent only and sends no HTTP. Add `--remote --out <new.json>` for a read-only visible inventory. The saved report includes resources, shared primitives, data counts/digests, native cascade metadata, operations and blockers. It is not an executable manifest, a backup or proof of write permissions. `--read-only` may accompany a remote preview.

Use `--with-data` only when destruction of the exclusive objects' data is within the user's scope. This operation differs from `model retire-object`: the governed `fm__object` deletion can trigger physical table removal, not a 30-day retirement. Do not describe it as reversible through a record restore. If a root resource is already blocked, data reads are limited to a diagnostic first page: `complete:false` and `count` describe only observed rows. Full data verification is deferred until the root blockers are resolved. No deletion is executable from that diagnostic report.

`--include-object <uuid>` explicitly includes an additional approved object, such as an unlinked object found during investigation. Repeat the flag for each object. A matching namespace/name is not automatic authority to delete; shared included objects are still preserved. Business-table relationships outside the selected object set block deletion even when the other table is empty, because physical cascades can affect its constraints.

Actual execution requires `--confirm <same-app-uuid>` and `--receipt <new.json>`. `--expected-tenant <uuid>` pins the verified remote tenant independently of the OAuth `default` storage alias; `--tenant` still selects the usual CLI session. Never replace a denied token/session silently. The UUID confirmation records intent and is not a server authorization check.

Execution rebuilds the inventory before its first write, records progress before each operation, checks authenticated identity and the draft app, and deletes the app last. Requests are sequential, not one transaction. A concurrent publication can race the client draft check. Failure/unknown response stops execution; there is no automatic retry, rollback, force flag, direct SQL or manual ledger purge. Preserve the receipt and inspect remote state before preparing another plan.

Missing/inaccessible resources are not proven absent. Incomplete pagination, unknown primitive kinds, external references, non-owner cascades, referenced schedules, active workflow runs and lifecycle name reservations block execution. The jobs API omits payloads, so pending queue activity cannot be attributed reliably to an app; it blocks cleanup rather than authorizing cancellation of unrelated work. Resolve blockers through their governed services; do not remove safety checks to get an executable preview. `--progress` prints inventory stages to stderr without mixing them into JSON stdout.

Postchecks verify successful collection reads for visible resources/name bindings and readability of preserved primitives. Hidden resources, arbitrary text/JSON references, external integrations and physical database catalog absence are not fully exposed by these APIs. Report the returned verification scope; do not promise universally residue-free cleanup or immediate name reuse beyond the verified evidence. Platform audit/archive records are retained according to server rules.
